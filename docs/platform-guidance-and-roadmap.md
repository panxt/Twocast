# 账号、使用边界与团队改造方案

核对于 2026-10-01。本次范围：配置与使用引导、边界提示、修复登出，以及管理员个人登录码。多团队、飞书登录和音频导入仅为后续方案。

## 账号与恢复

- 邀请码首次兑换创建账户；个人登录码回到同一个账户。再次兑换邀请码会创建另一账户。
- 设置 → 账号与登录：成员和管理员都可生成新个人码，旧个人码立即失效，当前浏览器不会退出。只显示一次，服务端存储哈希。
- 退出只轮换浏览器 token、清除 cookie，保留账户、登录码、节目、API 设置和分享。账户行目前兼作会话行，不能直接删除。
- 会话有效 30 天；另一个设备用个人码登录会替换旧设备的会话。此模型暂不支持同时保留多个设备会话。
- 忘记码但仍登录：自己生成新码。普通成员已经退出：管理员重置成员码。
- 管理员全部退出且个人码丢失：部署维护者使用 Vercel Production 环境的 `BOOTSTRAP_ADMIN_CODE`。若也丢失，维护者生成新随机恢复码、更新该环境变量并重新部署，再进入系统生成个人码。不要把恢复码存入 Git、普通设置或分享给成员。
- 恢复入口会新建管理员账户，仍可管理全站内容和全局模型。它不等于恢复旧管理员账户 ID；后续拆分账户与会话模型时应改为稳定身份恢复。
- 撤销其他管理员登录同时清空其个人登录码；已有恢复码须由部署维护者单独轮换。清理过期管理员记录时保留具有个人登录码的身份。

## 登录方式选择

| 方式 | 适用情况 | 后续工作 |
| --- | --- | --- |
| 邀请码 + 个人登录码 | 小规模内测、外部访客 | 保留作为访客入口；个人码在密码管理器保存，管理员提供重置 |
| 每人设置密码 | 不依赖企业平台的长期独立用户 | 采用成熟认证服务；需要身份绑定、找回、速率限制与独立会话，不能只加密码输入框 |
| 飞书登录 | 已在飞书工作的内部团队 | 优先作为内部团队入口；保留邀请码供外部访客 |

建议内部成员用飞书，外部访客沿用登录码。飞书需企业自建应用、App ID/Secret、回调白名单、应用发布及必要的用户信息权限。服务端验证授权回调和 state，以 tenant_key + 稳定用户标识映射账户；不能靠昵称或同名部门授予权限。飞书登录验证身份，站内团队仍负责授权。无需本次就申请通讯录全量权限。

官方参考：https://open.feishu.cn/solutions/detail/qrcode?lang=zh-CN

## 模型配置

聊天配置：完整 Chat Completions URL + 模型 ID + 对应 API Key。MiniMax 示例在设置中只填空白 URL/模型，不覆盖已配置值，不保存或填入密钥。

- 国内站示例：`https://api.minimax.cn/v1/chat/completions`。
- 国际站示例：`https://api.minimax.io/v1/chat/completions`。
- 模型示例：`MiniMax-M2.7`；账户可用模型以服务商控制台为准。
- MiniMax 语音目前仍走国内站接入，需要对应 Key 和 Group ID。聊天和语音可以使用不同提供商，聊天 Key 与语音 Key 分开配置。
- 普通用户聊天 URL 只允许已接入服务域名，且协议须兼容当前请求。获得域名许可不等于支持该厂商的所有原生协议。
- 主题生成需搜索模型；目前仅对 api.x.ai 自动启用搜索参数，不能把普通聊天模型称为联网搜索服务。
- 使用正文或文档进行小样本生成可确认权限；保存配置本身并不调用付费模型，也不保证 Key 有余额。

参考：https://platform.minimax.cn/docs/api-reference/text-openai-api 和 https://platform.minimax.io/docs/api-reference/text-openai-api

## 输入能力

当前支持主题、公开网页、PDF、UTF-8 TXT/Markdown 和粘贴正文。博客已经可作为资料导入。生成是整理改写，不保证逐字朗读全文。

网页提取的是服务端可访问页面的 body 文字，不包含视频音轨转录。B 站生成成功可能仅基于标题、简介或页面可见文字；不代表获取了视频完整内容。若需准确覆盖视频，当前应提供字幕正文。扫描 PDF 需先 OCR。

已有音频还不能直接导入；现有入口是生成资料输入，并非音频资产导入。

## 多团队方案（未实现）

当前只有 `team_access` 和 `visibility=team`，所有获准团队成员共享一个全站空间，目录和标签不构成权限隔离。

建议先拆分稳定账户与独立浏览器会话，再增加：

- `teams`：团队名称、状态、负责人。
- `team_members`：账户与团队多对多关系、成员/团队管理员角色。
- `invite_teams`：邀请码可绑定一个或多个团队，兑换时由后端授予关系。
- `episode_team_shares`：节目明确共享到指定团队。私人内容默认不共享；加入团队不自动公开已有私人内容。

平台管理员管理所有团队；团队管理员只管理其团队。成员可属于多团队。列表、目录、源文件、音频、歌词、封面、下载包及签名 URL 的后端授权全部使用同一团队判定，不能仅在 UI 筛选。普通成员 API 分享对象也应收缩为有共同团队的成员，跨团队分享需要明确策略。API 调用额度与内容读取权限分开。

迁移时把旧全站共享映射到一个明确的「原团队」，仅原有 team_access 成员加入；新增团队不自动继承旧共享。普通角色通过后端服务访问，新增公开 schema 表开启 RLS，不给匿名角色开放内容。验证跨团队直接请求 UUID、下载链接、移除成员、邀请多个团队等场景。

## 内容导入方案（未实现）

1. 博客作为资料：当前正文、公开链接和 Markdown 已支持。
2. 已完成播客作为作品：独立导入入口，先支持 MP3/WAV、标题、目录、私有/指定团队；可附 TXT 脚本或 LRC，不触发 LLM/TTS，也不消耗生成授权。
3. 音频通过短期、限定用户路径的签名上传直接进入私有存储，绕开 Vercel 请求体限制。服务端完成后验证文件大小、真实格式、时长及拥有者，再入库。未确认的上传需清理。
4. 只有正文不能推断精准时间轴；有 LRC 则验证时间戳，缺少时间轴先显示普通脚本。可另行提供需明确选择的 ASR/强制对齐服务，说明额外 API 与费用。
5. 后续音频转写成新资料，以及 ZIP 导入音频+脚本+封面，分别增加异步处理和防重复导入。

导入前应定好团队归属和稳定账户模型，避免随后重新迁移资产权限。

## 实际资源和边界

站内限制由 `src/lib/podcast/limits.ts` 共享：文档 4,000,000 字节，PDF 200 页，正文/提取文字 100,000 个 JS 字符；封面 3,000,000 字节。生产每账户每日 3 期（含失败记录，UTC 日期，北京时间 08:00 重置），同一时间最多 1 条未完成任务。邀请码每日次数是参考统计，不限制兑换。

2026-10-01 的数据库查询快照：

| 内容 | 对象数 | 对象元数据大小合计 |
| --- | ---: | ---: |
| 音频（含临时片段） | 10 | 77,642,877 字节 |
| 原文件 | 2 | 29,854 字节 |
| 封面 | 1 | 309,727 字节 |
| 合计 | 13 | 77,982,458 字节（约 78 MB） |

数据库物理大小约 11,889,811 字节（11.9 MB）。以上是瞬时元数据/物理大小，不等于平台月度计费用量或组织剩余额度。

实际桶配置均为私有：podcast-files 4,000,000 字节；podcast-covers 3,000,000 字节；podcast-audio 104,857,600 字节（100 MiB）。桶配置不能突破平台套餐的全局单文件上限。

官方免费方案参考（本次未通过账单接口确认组织当前套餐，不能当作账户实时额度）：

- Supabase：文件存储 1 GB，数据库 500 MB/项目；普通出站及缓存出站流量各 5 GB，存储单文件最大 50 MB。实际以组织套餐、使用量和全局/桶配置中较小的限制为准。
- Vercel：函数请求及响应整体最大 4.5 MB；Hobby + Fluid Compute 的内存 2 GB，单次函数最长 300 秒。后台工作流每步受执行时间约束，整期耗时不等于单步时限。
- 音频在 Supabase 长期存储，Vercel 临时内存/磁盘不计算为长期文件容量。在线播放及下载消耗存储服务出站流量；API token/语音额度另算。
- 按 128 kbps、10 分钟估算一条 MP3 约 9.6 MB。1 GB 仅约容纳百条此类音频，实际还需原文件、封面、临时片段和余量；不是保证期数。

本次在创建表单和设置中展示上述说明，新增明确的正文超长、PDF 页数、413 请求过大、存储大小/空间/权限/频率和 504 超时提示。尚无实时套餐额度仪表盘；后续可增加管理员存储用量页、接近阈值提醒、临时文件清理和管理员可配的生成次数。

官方参考：https://supabase.com/pricing 与 https://vercel.com/docs/functions/limitations
